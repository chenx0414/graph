## 启用与回退

默认 APP 的 `~/.graph/app-root` 当前指向本工作区。用户已明确批准重载默认 APP，现已正常退出并重新打开同一默认应用。新守护进程从当前工作区加载源码与 Web，健康检查通过，静态脚本通过真实 HTTP 确认使用 gzip 且解压后与构建文件逐字节一致。未替换 `/Applications/Graph.app` 或推送。

[huashu-flash](https://github.com/alchaincyf/huashu-flash/blob/master/SKILL.md) 要求“上线必须用户批准”。该批准已收到并执行。重载前确认 `activeOperations=0`、`operationsKnown=true`，原窗口位于模型页面；正常退出后恢复原有会话窗口。这里是本地启用，不需要 DNS/CDN 配置或新托管服务。

回退时只撤销本轮 diff：`vite.config.ts` 的压缩插件、`scripts/compress-web-assets.ts`、`src/server/app.ts` 末尾 assets 路由新增的压缩分支、`src/web/App.tsx` 的五项 lazy 页面加载；保留这些文件中任务开始前的用户修改，然后重建 Web、在安全时重载。优化前页面构建保存在 `/tmp/graph-flash-baseline-web`，只复制 Web 不能回退守护进程源码。未生成独立提交，因此禁止用整文件 `git restore` 破坏已有工作。

静态服务保留逐请求读盘，不持有旧构建缓存；构建时生成压缩文件，避免运行时 CPU 开销；原文件一直保留给不接受 gzip 的客户端。额外成本是构建耗时约几十毫秒和压缩文件磁盘占用；设置、能力库等页面首次打开增加按需请求，短暂显示既有 Spinner，后续复用模块。测速脚本也通过独立 TypeScript 检查。完整检查日志位于 `/tmp/graph-flash-check-final.log`。Node/浏览器版本、机器负载会影响毫秒级/帧级差异，后续需用同样的配对口径复验。
