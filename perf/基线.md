# 基线（2026-11-16）

机器：macmini（本机，App + daemon 已运行）。
测量：`curl -w %{time_total}`，同一时段连续 10 次，报 p50/p75/max。

## 端点

| 端点 | p50 | p75 | max | 响应大小 |
|---|---|---|---|---|
| `GET /api/conversations/ebd518f3…`（Main） | 1.209s | 1.762s | 9.437s | 1,033,894 B |
| `GET /api/conversations/…/history` | 0.005s | 0.010s | 0.027s | 87,011 B |
| `GET /api/fleet` | 1.504s | 1.968s | 2.107s | 230,133 B |
| `GET /api/catalog` | 0.009s | — | — | 269,608 B |
| `GET /api/providers/magpie` | 0.011s | — | — | 1,812 B |

`/api/conversations/{id}/history` 只做一次 messages 查询，5–10ms；同一个会话的完整 View 却要 1.2s，说明慢在 View 里的派生统计，不在消息读取。

## 首屏拆解（SQL 实测）

- `messages`：20,389 行；最近 200 条查询 10ms，已走 `messages_scope(conversation_id,seq)`。
- `invocations`（Main anchor 任务）：**50,065 行**；`InvocationRows` 把每一行的 `usage`/`cost` JSON 全部解析。
- `ConversationMasterUsage` 再扫同一批 50,065 行两遍（汇总 + 找最新 completion），每行还有一次 `json_extract(n.spec,'$.role')` 的 EXISTS 子查询。
- `events` 17,358 行；`MAX(cursor)` 走索引，可忽略。

## 确定性计数

- 每次 `/api/conversations/{id}` View：50,065 条 invocation 行被读出；约 100,130 次 JSON 解码（usage+cost）。
- 这条路径每 3 秒被 UI 刷新调用一次，即使没有新回合。

## 结论

主指标瓶颈在 `ConversationMasterUsage` 与 `taskRuntimeTaskCost` 的全量 invocation 扫描/解码，不在 SQLite 索引或消息分页。
