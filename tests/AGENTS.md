# 测试归属

- 新增或迁移测试前读取 [test-audit](../.agents/skills/test-audit/SKILL.md)。每项独立契约指定一个主要 keeper；旧层在真实 keeper 通过与保留性复核后退休。
- E2E 通过实际浏览器、HTTP、CLI 或公开运行程序驱动完整业务，使用真实持久化和必要的进程、Git、传输。受控外部模型服务可以替代远端供应商；自有协作者生成的回执、顺序和状态由实际 owner 产生。
- 测试分类与退休依据记录在 [审计账本](../docs/planning/test-audit-2026-10-14.md)。混合文件逐声明判断，文件名含 `e2e` 本身不是证明；已有单元、集成测试可运行与审计；新增或改写的测试只能是完整 E2E，必要契约迁入真实 E2E 后才可退休旧层。
- 持久化夹具用真实写入者生成 invocation、receipt 和顺序。外部恢复输入说明来源与修改范围，验证它实际能证明的兼容契约。
- 等待可观察结果后断言；负向断言先证明目标元素、请求或 guard 存在。真实失败回归应在修复前失败、修复后通过；故障注入后逐字节恢复生产源码。
- Vitest 运行期间冻结该检出内的源码、测试、共享夹具和可执行分组清单；并行审计先写临时计划，运行结束后统一应用。

- 只允许编写 E2E 测试，禁止新增或改写单元、集成测试。规则同样约束主 Agent、子 Agent、工作节点和审查者。
