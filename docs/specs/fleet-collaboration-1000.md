# 千级 Agent 协作交付

日期：2026-11-13。用户授权按优先级完善 Graph，支持 1000 个以上 Agent 围绕同一个目标工作。设计遵循极简、稳定、低内存、快速、可扩展、可视化；优先复用现有能力。

## 完成条件

- 一个目标由长期主管持有，工作沿 Agent 父子关系委派；至少 1024 个工作 Agent 可在配置允许时同时进入真实执行路径。
- 通过可控 provider 的确定性屏障观察并发执行，不以登记行数、配置值或 limiter 单测冒充执行证据。供应商限流与本地执行容量分别记录。
- 父级可分页读取子级历史、列出直接子级、追加指令、停止子级；越权访问拒绝，暂停与归档语义继续成立。
- 子级成功与失败回报携带来源与 execution 身份；重复结算不重复消息，后续回合不会被前一回合的去重键吞掉。
- 编队、任务与产物随后台工作更新；点击产物抵达指定版本；千级展示保持聚合与有界数据读取。
- 验证包含真实 daemon、SQLite、受控模型与协作结果，报告执行数量、结果一致性和资源观测。真实付费模型的吞吐受配置与供应商限流约束，不能由受控模型测试代替。

## 实施顺序与检查清单

- [x] 阅读 poteto-mode 的 Principles、工程规范、领域术语、v2 规格与 ADR 0043。
- [x] Frame：核对现有实现并定义上述完成条件。
- [x] Design：将工作划为三个独立单元，先复用既有运行链，再由实验决定容量修复。
- [x] 单元一：先写失败测试，补全动态子 Agent 管理与生命周期。
- [x] 单元二：先写失败测试，连通原生界面刷新与指定产物导航。
- [x] 单元三：先建立真实执行容量和协作验收，再修复测试暴露的调度、持久化或恢复问题。
- [ ] 集成：核对权限、幂等、失败与恢复；移除本次触及的冗余代码与解释性注释，更新过时说明。
- [ ] Verify：运行定向验证、激活门禁、独立审查和原生界面验证，保存可复跑命令与结果。
- [ ] Hand back：检查证据，合并工作成果并清理所有派生 worktree 与分支。

## 工作边界

复用 PiG durable 会话、Agent 登记表、现有执行器、权限与预算门、SQLite 和 MyGo。当前形状已有 ADR，不先重写运行内核，也不新增调度服务。预计涉及三个工作单元、约 15 至 30 个实现及测试文件；以失败测试暴露的事实调整范围。

采用高强度验证，因为并发、恢复和父子控制会影响用户正在委派的工作。所有行为改动先红后绿，测试不依赖 sleep、耗时或随调度变化的重试次数。测试与测量使用临时状态，不调用用户的生产模型或修改生产会话。性能数据记录环境与瓶颈；资源观测不作为易受机器负载影响的测试断言。

## 决策与证据

决策记录位于 `docs/reports/fleet-collaboration-1000.tsv`。各实现单元记录失败测试命令、失败原因、修复后命令及输出位置。最终验收明确区分 VERIFIED、NOT VERIFIED 与 INCONCLUSIVE。
