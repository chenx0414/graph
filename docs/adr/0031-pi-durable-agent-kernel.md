# ADR 0031：main 与节点统一使用 pi-durable 1.1.0

Graph 的自建 Agent 执行与恢复路径改用 `@earendil-works/pi-durable` 1.1.0，main 和 graph 内节点都采用持久会话与任务，避免两套执行机制承担恢复。使用者于 2026-10-12 确认可以清空旧 graph 执行历史，但必须保留 main 会话和配置；接口投递、动态修改、预算、产物和验收仍是 Graph 的产品契约。

## 对既有决策的影响

取代 ADR 0030 中每节点常驻 Pi 进程和旧 SDK 负责执行恢复的实现选择；保留其接口投递模型、同一个 SQLite 正式存储与单一执行路径要求。durable 的 task ownership 图不替代用户的 Graph 定义，durable 的输入 submission 也不等同于 Graph 的具名输出提交。

## 实施边界

同一存储由单一宿主持有；durable 表与 Graph 业务表明确隔离。存储适配和业务命令幂等受理必须用真实 SQLite、上游存储契约与崩溃测试证明，不能假定两个库的事务自动相通。外部工具副作用保持不确定性，不能因引入 durable 就宣称任意工具可以安全重放。

切换前备份数据库和 main 原始会话，转换不得重放历史工具或模型调用。旧 graph 运行可退役，清理不得扩大至配置、配方、共享产物、用户工作副本或 Git 成果；完成切换后只保留 durable 执行路径。
