# ADR 0024：完全访问策略

日期：2026-09-19

## 状态

已接受；2026-09-21 根据使用者确认的“完全访问全部放开”修订。

## 背景

Graph 当前把问题审批、任务授权、命令白名单、Agent 路径边界、MCP 网络声明和 Pi
extension 运行时声明分别实现。使用者需要一个默认启用的完全访问模式，让 Graph
自动处理运行授权、访问宿主工作路径，并运行能力声明的命令和网络，而不需要把
这些边界散落成多个 `fullAccess === true` 分支。修订后的完全访问还要求暂停、
预算、未知用量、恢复问题和讨论期只读策略不再阻止 Agent 调用自己的工具与能力。

绝对“所有路径”和同一 OS 用户下的宿主凭据隔离不能同时成立。完全访问允许 Agent
读取 `$HOME/.ssh`、`.aws`、`.netrc`、Git credential store 和 Graph 正式状态，
因此不能承诺宿主凭证隔离。需要绝对隔离的执行身份仍应使用独立 OS 用户、容器或
VM。

## 决策

- 配置新增版本化 `access` 文档，默认使用 `full`；`standard` 仍可显式选择以恢复
  原有的工作区、命令白名单、声明网络和权限审批边界。
- `full` 预设自动批准 `permission` 和 `system_change`，允许宿主文件系统、任意
  可执行命令、任意网络、Pi extension 宿主运行时、本地绑定、全部 Unix socket、
  Apple Events、Git metadata 写入和 credential stores 访问。
- `full` 下暂停、预算、未知用量、恢复问题和讨论期只读策略不再阻塞派发或工具调用。
  操作、invocation、用量与事件仍写入正式记录，供界面、计量和审计查看，但这些记录
  不反向形成权限门。
- `human_check`、模型订阅决策、任务图确认和并发上限仍是独立控制面；它们不属于
  Agent 调用自己能力的目录、网络、命令、权限或恢复边界。
- 每次 operation 在准入时冻结 effective policy 和 digest。运行中的 operation
  不因热配置变化扩大权限；回退只影响下一次准入。
- 自动批准复用正常问题答案路径，保留原始问题、自动答案、策略 digest 和审计事件。
- 命令始终以 executable + argv 执行，不把模型输入拼成 shell 文本。

## 后果

完全访问模式在当前 macOS 同一用户模型下放开工作路径、命令、网络、能力运行时、
暂停、预算、用量与恢复门，但不能承诺宿主凭证绝对隔离。需要绝对隔离时必须选择
独立执行身份。

使用者随后确认了界面修订：完全访问开关放在聊天输入区，点击即可开启或关闭，
不再要求输入 typed phrase。默认状态为开启。运行权限仍在 operation 准入时冻结，
界面开关只改变下一次准入使用的配置；effective roots、网络、命令、受保护路径和
策略 digest 继续保存在有效配置与 operation 审计记录中。

新策略进入 operation 记录，不重写历史 `task_grants`、预算、credential groups
或历史事件。回退不会撤销已经发出的外部副作用，这些副作用继续走恢复和核对。
