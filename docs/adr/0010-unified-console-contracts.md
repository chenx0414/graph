# 统一控制台契约：无限额、Git 准入、热生效、会话投影与统计

状态：2026-09-15 已确立，U01–U10 按此实施；尚未完成整体验收。未知用量部分由 [ADR 0017](0017-unlimited-unknown-usage.md) 收窄：不限额度的主 Agent 不再因缺失 usage 阻塞，子 Agent 与有限预算实例继续 fail-closed。计划见 [统一控制台实施计划](../planning/unified-console-roadmap-2026-09-15.md)，基线报告见 [U00 报告](../planning/unified-console-u00-report-2026-09-15.md)。本 ADR 只固定契约，不表示功能已实现。

## 背景

合并后的 `feat/unified-console` 同时包含会话优先主 Agent 入口与桌面 APP。本轮用户提出八项要求，其中若干与旧默认冲突（旧规格默认单实例累计 20,000,000 token），另有一批此前没有明确定义的边界（热重载、真实 Git 准入、节点会话投影、人才经历统计）。若不为这些边界固定一份契约，各工作包会各自定义一套状态，造成账本分叉。

## 决策

### 1. 默认不限累计 token，账本与门禁不变

- 新会话、任务、实例的默认策略为 `tokenLimit = null`、`runTimeLimitMs = null`；`null` 明确表示“不设累计上限”，不使用 `Infinity`、超大数字或 `0` 表示。
- 预留与已用量仍是有限整数；只有预算比较在 unlimited 时跳过。单次调用仍需通过暂停、权限、10 个 Agent 名额、凭据并发、实例身份与恢复规则；缺失 usage 在不限额度的主 Agent 上记录为未知并继续，子 Agent 与有限预算实例仍 fail-closed。
- 模型上下文窗口、单次最大输出、并发名额与累计预算是不同参数；无限累计不放宽协议限制。
- 旧实例的 `budget` 与 `used` 原样保留，不因迁移被重置或扩大；迁移只新增“是否无限”的判别字段，并默认所有存量实例为有限。数据库中恰好为 20,000,000 的值不得被当作“未经用户设置的默认”自动改写。
- 用户配置有限额度后，发送前仍按现有路径阻断并生成预算问题；有限实例可经明确操作切换为无限，反向切换也需明确操作。
- “不限总时长”只移除 Agent/任务执行总时长的默认截止；网络建连、IPC 握手、关闭清理、失联核查与测试进程的超时保留，并展示真实原因。已确认的程序检查命令超时不能在执行中静默修改。

### 2. 正式派发只在 Git 项目内进行

- 业务项目在执行前必须具备可用 Git 仓库与本地基线。宿主负责准备：识别 workspace/submodule/worktree、初始化非仓库、生成受控的基线快照提交；记录 detected / initializing / ready / failed 与 repoRoot、projectSubdir、branch、baselineSha。
- 初始化基线只纳入可见项目文件；按现有 ignore 与敏感/生成文件排除策略排除 `.env`、凭据、Graph 状态目录等，禁止无说明的全量 `add`。宿主不改全局 Git 配置、不配置 remote、不 push。
- 已有脏改动的仓库默认阻断正式执行，不显示“已准备好”；页面提供查看未提交修改与“明确创建本地基线提交”的入口，由用户选定范围后宿主提交，或等待用户自行整理。不自动替用户 reset/覆盖/提交既有改动。
- 未选择项目的普通聊天仍允许；会话 anchor 的内部 scratch 属于宿主状态空间，不作为未登记业务项目使用。
- 直接调用 REST/Runtime 也不能绕过执行准入；无 Git 的项目在派发工人前失败并给出可处理状态。

### 3. 配置热生效按“已应用 revision”定义

- 宿主只有一个 ConfigManager，持有不可变运行配置快照、凭据版本与有效 revision。保存流程为校验、准备候选绑定、持久化、激活、发事件；任一步失败保持旧有效配置，不返回虚假成功。
- 生效边界：
  - 新增供应商/模型、解除首次未配置：保存成功后可用于新派发，不需重启 APP 或 daemon。
  - key 轮换：已发送调用保持旧凭据至结算；尚未发送的请求在发送前重新解析并使用新凭据。
  - key 禁用/撤销：阻止新发送；不截断已经发出的响应。
  - 每 key/共享组并发调整：修改同一宿主调度器；已有调用保留计数，降低限制后等待自然回落。
  - 默认模型/等级策略：新实例与后续选型使用新策略；运行实例不静默换模型。
  - 模型端点、协议、能力版本：已开始 operation 固定其执行契约；下一安全派发边界切换并记录新版本。
  - 价格刷新：新 invocation 绑定新价格快照；旧 invocation 估算不被重算。
  - 新默认 token/时间策略：新实例使用新默认，存量实例只有经明确操作才变更。
- 不能通过 relaunch、关闭 daemon、重建会话、清空队列或重开窗口冒充热生效；成功提示必须对应真实 revision 与实际发送绑定。
- 排队请求在发送前重新解析 key/身份/限制；需要更换队列身份时归还旧名额并重排；不允许把另一平台的新 key 发给旧 endpoint。平台或端点同时变化的未发送工作安全重新准备或进入明确待处理状态，保留实例与会话，不猜测兼容性发送。
- 密钥只经受权限的本机通道交给 daemon，不进入普通配置 DTO、事件、日志或浏览器持久存储；凭据存储失败不得展示“已连接”。CLI 的 env 适配保留，纯浏览器使用同一权限边界。

### 4. 节点详情来自真实 Pi 会话与执行账本

- 严格区分：Agent 定义（可复用、带版本）、Agent 实例（任务内工作者，返工沿用）、activation（节点的一次激活）、operation（一次执行尝试）、invocation（一次真实供应商调用）、session/entry（Pi 会话与消息记录）。
- 工人与审查实例接入真实 Pi 事件；正文、工具调用与结果摘要持久化为展示记录，会话文件仍是上下文来源。不得从最终 output 伪造对话，不把同一消息双写成两份用户可见记录。
- `NodeRunView` 为只读投影：正文、工具活动、实际模型/定义/能力版本、用量与价格快照、运行/等待时间分段、产物/问题/证据；工具区区分定义绑定、已加载、当前可执行、因讨论模式/授权被禁用。
- 程序节点展示命令、退出码、stdout/stderr 与证据；容器展示子节点；草稿显示尚未运行。
- API 以实体 ID 定位记录，不接受浏览器任意文件路径；记录不可得时显示未记录；流式、历史分页与重启恢复使用明确的覆盖/版本契约（含 `after` 游标），不按全局 seq 连续性推断缺页。详情默认只读，不启动新 Agent、不插话、不触发工具。

### 5. 统计按指标独立判断完整性

- token 按 invocation ID 去重，使用归一化权威用量；已知小计与未知调用数分别展示，unknown 不折为 0。
- 费用显示币种与估算性质，使用派发时的价格版本；缺价格/无法准确表达时显示未知或部分估算；不同币种不直接相加。
- 总历时为首次进入执行到终态的时间（含等待）；运行时间为实际工作时段之和；排队、暂停、等待用户分别列示；凭据排队不计入运行时间，HTTP 在途计入运行。时间分段按状态边界写账。
- 平均 token/运行时间默认统计选定定义版本、已结束经历中的完整样本，显示样本数、失败数、未知数与未结束数；跨版本统计用总和/总样本数，不平均各版本均值。
- 完整性按指标分别判断：token 已知而价格未知仍计入 token 均值；时间完整而 token 未知仍计入时间均值；每项显示自己的分母。
- 无记录显示“暂无”；缺历史时间段显示“未记录”，不为旧数据补造精确时长。
- 主管聊天属于真实工作但单列“对话工作”样本，不与功能任务实施经历混算。

## 后果与限制

- 契约中的状态与 DTO 由集成负责人在 `store.ts` 迁移号、配置 schema 与 `task-runtime.ts` 公共接口中统一排号；各工作包不得自行新增一套重复状态。
- 长会话自动摘要/压缩仍未实现；本轮 UI 不作无限上下文的承诺。真实模型对话质量评估仍未执行。
- OAuth 订阅登录、多云企业身份与 RPM/TPM/429 冷却不在本轮承诺内。
- 本 ADR 不修改历史验收报告的结论；只约束当前生效规格与后续实现。
