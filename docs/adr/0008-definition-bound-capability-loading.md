# 能力按定义版本在受限边界内加载

Agent 定义版本绑定能力 ID 与版本。生产实例打开时按绑定解析并加载这些能力，而不是只在任务说明里列出 ID：

- Skill 作为 Pi 资源加载器中的只读资源进入系统提示，模型可通过工作区读取入口读取快照内文件。
- 本地 MCP 通过真实 stdio JSON-RPC 暴露工具；每次调用启动一个操作系统受限进程，经与模型请求相同的 send gate，因此调用可计量、暂停时不会启动新进程，且写入范围不超出工作副本与 Graph scratch。
- 扩展不在正式后台进程加载。受限 executor 用宿主自带的 `extension-worker.mjs` 启动一个沙箱进程，扩展只看到最小 `register(api)` 接口；工具同样每次调用一个进程并过 send gate，工作进程无法读写授权范围外的路径。
- 远程 MCP 通过 Streamable HTTP JSON-RPC 调用，只在运行时授予的域名白名单内放行；调用经同一 send gate，凭据来自 `capability.json` 的 `headers`/`headersEnv`，不回写正式库。
- 网络资料检索由受控读取 broker 提供：只允许运行时授予的域名，拒绝重定向与内嵌凭据，只接受文本类响应并限制大小，每次请求过同一 send gate，因此暂停与额度规则同样生效。

能力加载不写入 `task_grants`，安装能力也不会扩大任务权限；域名放行不授权外部写操作。相比把能力 ID 写进说明包或让主管在后台进程直接加载扩展，这一选择要求更多受限进程与协议代码，但保住了“安装不等于授权”和批量暂停、记账、恢复规则的一致性。扩展 worker 只实现本仓库定义的最小工具协议，官方 Pi 扩展 API 的完整语义仍不在此列；其他平台与远程 MCP 的其他 transport 未验证。
