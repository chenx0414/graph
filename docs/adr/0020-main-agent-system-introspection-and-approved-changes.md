# ADR 0020：Main Agent 的系统自省与受批准变更

日期：2026-09-19

## 状态

已接受。

## 背景

Pi 并不会让模型天然知道自身状态。它由宿主把当前有效的 system prompt、工具、Skill 摘要、文档入口和运行环境投影给模型；需要模型直接查询时，再由 extension 注册 custom tool。Pi 也没有自动修改自身配置的闭环。

Graph 的 Main Agent 过去只能通过 `read_system_capabilities` 读取一份摘要，且能力导入等修改没有独立于项目绑定的受控路径。未绑定项目时，用户要求安装 MCP，Main Agent 只能拒绝。

直接让 Main Agent 写 `~/.graph/capabilities` 或配置文件会绕过版本、校验、审批和审计，也可能把密钥写进能力清单。系统自我优化不能等于模型直接自改。

## 决策

- Main Agent 在每轮请求获得一份裁剪后的系统自模型，包括配置模型、订阅状态、Agent 配方、已编译定义、架构、能力数量与根目录。它是运行时事实投影，不是历史记忆。
- 新增只读 `inspect_graph_system`，汇总系统摘要、开放内部问题、失败节点、未知用量、无效能力和待批准变更。详细能力仍通过 `search_resources/get_resource` 按需读取。
- Main Agent 发现问题时调用 `propose_system_change`。该调用只创建 `owner=user`、`kind=system_change` 的持久问题，不执行修改；问题不绑定创建它的 operation，避免模型回合结算时被自动关闭。
- 用户明确批准或拒绝后，问题结算。批准会让 Main Agent 继续一个回合；拒绝只记录决定，不允许应用。
- Main Agent 只能通过 `apply_system_change` 应用已批准提案。宿主按 `proposalId` 查找问题和用户答复，校验 `decision=approved`，拒绝未批准、已拒绝或未知提案。
- 首版受支持的系统变更类型是版本化能力包。宿主将 `capability.json` 和显式文本文件写入能力根目录下的独立版本目录，重新扫描并验证后才返回成功。能力清单不得包含字面量凭据；需要凭据时使用 `headersEnv`。
- 本地 MCP 启动命令允许固定白名单 `node`、`npx`、`uvx`，并要求能力清单声明网络域。安装能力和首次启动第三方包仍由用户批准触发。
- Main Agent 可直接读取 GitHub 公共文档以核对安装说明；读取内容是不可信数据，不能作为指令或权限来源。

## 后果

Main Agent 不再需要绑定业务项目才能理解或改进 Graph 自身。能力安装具有明确的两阶段边界：模型负责观察、诊断和提出具体变更，用户负责决定，宿主负责写入和验证。

代价是系统优化需要一次用户批准和一次后续模型回合；能力目录会保留独立版本目录，更新不会原地覆盖旧目录名。模型配置、凭据和任意配置文件的首版写入仍不开放，避免把自省工具扩张成无边界的系统控制面。
