# ADR 0028：应用运行产品线，自改的根就是它

日期：2026-09-22

## 状态

已接受。

## 背景

桌面应用从自己的 checkout 运行守护进程：哪个 checkout 被执行，守护进程就从哪里加载 `src/server/cli.ts`，也就从哪里服务 `dist/web`。自改（RSI）改的正是这棵树的源代码，激活后应用重载并运行新提交——两者必须是同一棵树，否则“已生效”无从谈起。

单一根出过一次真实事故：产品功能只存在于 `feat/app-ux` 分支，而应用运行的 checkout 在 `rsi/*` 分支上；一次范围里含 `desktop/` 的激活触发 `app:build`，`build:web` 从 `rsi` 树重建控制台，把先前手工部署的、含功能的控制台产物覆盖掉，应用里的复制/粘贴功能凭空消失。

此前只有 `GRAPH_RSI_ROOT` 一个开关，而它只存在于启动应用的那个 shell 的环境里；从 Finder 启动的应用没有这个环境变量，于是一个“指向哪里”的决定会在启动方式之间悄悄漂移。

## 决策

1. 应用运行的根由 `graphHome` 下的 `app-root` 文件决定（一行 checkout 路径）。文件是持久设定，任何启动方式都能读到；`GRAPH_RSI_ROOT` 保留为开发运行时的覆盖。
2. 只有真正能服务控制台的 checkout 会被接受（同时存在 `src/server/cli.ts` 与 `dist/web/index.html`）；半准备好的 checkout 被跳过，而不是让窗口空白。
3. 这个根就是产品线。自改的根与它相同：`apply_rsi_change` 在非 `rsi/` 分支上新建 `rsi/<slug>-<id>` 分支，因此自改从产品线切出，那棵树的 `app:build` 永远包含产品功能。

## 后果

- `app:build` 只可能从包含产品功能的树重建控制台：功能不会再被一次构建挤掉。
- 工作区 checkout 不再同时承担“应用运行”与“自改构建”两件事；自改的构建、测试与提交都发生在专用的根里。
- 换根在下次守护进程启动时生效：应用重载（或重启）后读一次根文件。
- 若根文件指向一个残缺的 checkout，应用会退回上一个可用来源（环境变量，或应用自带目录），不会白屏。
