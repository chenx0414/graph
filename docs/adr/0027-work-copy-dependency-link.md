# ADR 0027：工作副本的依赖链接对 Agent 命令同样生效

日期：2026-09-22

## 状态

已接受。

## 背景

每个 Agent 实例在自己的 Git 工作副本里工作，副本是新建的、磁盘上保持无依赖。此前只有确认的程序检查（`graph.command`）会在运行前把项目根的 `node_modules` 链接进副本；Agent 命令（bash 工具、`node --run …`）没有这条链路，实现 Agent 只能自己手动软链，否则项目自带工具链在副本里不可见。手动软链既容易忘记，也可能被 `git add -A` 提交出去——一个指向开发者本机绝对路径的软链进入集成分支或目标分支就是污染。

## 决策

1. 依赖链接由宿主持有，抽成单一入口 `linkProjectDependencies(workspace, candidate)`：解析候选目录（项目根的 `node_modules`，宿主可显式覆盖），副本内不存在链接时建立软链，返回解析后的真实路径供沙箱读取授权使用。程序检查与 Agent 命令共用同一入口。
2. Agent 操作在打开工作区命令运行器之前完成链接（`pi-adapter`），并把返回路径作为 `readPaths` 交给沙箱：链接目标在副本之外，没有读取授权就无法解析。
3. 链接绝不提交：创建 worktree 时宿主写入仓库本地忽略表（`.git/info/exclude`，从不提交），其中 `node_modules` 使用无尾斜杠模式——软链不是目录，`node_modules/` 这类目录专用模式匹配不到它。同一原因也让 baseline 与 `git add -A` 都看不到它。

## 后果

- 实现与审查 Agent 在副本里可直接运行项目自带命令，不必手动软链；副本仍保持无依赖，一份安装在所有副本间共享。
- 项目未安装依赖时链接为空，命令按自身错误报告解析失败，行为与今天一致。
- 单仓多包（依赖装在仓库根、项目根是子目录）仍需宿主显式给出 `nodeModulesPath`，与检查路径的既有边界一致。
