# ADR 0027：工作副本的依赖链接对 Agent 命令同样生效

日期：2026-09-22

## 状态

已接受。

## 背景

每个 Agent 实例在自己的 Git 工作副本里工作，副本是新建的、磁盘上保持无依赖。此前只有确认的程序检查（`graph.command`）会在运行前把项目根的 `node_modules` 链接进副本；Agent 命令（bash 工具、`node --run …`）没有这条链路，实现 Agent 只能自己手动软链，否则项目自带工具链在副本里不可见。手动软链既容易忘记，也可能被 `git add -A` 提交出去——一个指向开发者本机绝对路径的软链进入集成分支或目标分支就是污染。

## 决策

1. 依赖链接由宿主持有，抽成单一入口 `linkProjectDependencies(workspace, candidate)`：解析候选目录（项目根的 `node_modules`，宿主可显式覆盖），副本内不存在链接时建立软链，返回解析后的真实路径供沙箱读取授权使用。程序检查与 Agent 命令共用同一入口。
2. Agent 操作在打开工作区命令运行器之前完成链接（`pi-adapter`），并把返回路径作为 `readPaths` 交给沙箱：链接目标在副本之外，没有读取授权就无法解析。
3. 链接绝不提交：创建 worktree 时宿主写入仓库本地忽略表（`.git/info/exclude`，从不提交），其中 `node_modules` 使用无尾斜杠模式——软链不是目录，`node_modules/` 这类目录专用模式匹配不到它。同一原因也让 baseline 与 `git add -A` 都看不到它。

## 后果

- 实现与审查 Agent 在副本里可直接运行项目自带命令，不必手动软链；副本仍保持无依赖，一份安装在所有副本间共享。
- 项目未安装依赖时链接为空，命令按自身错误报告解析失败，行为与今天一致。
- 单仓多包（依赖装在仓库根、项目根是子目录）仍需宿主显式给出 `nodeModulesPath`，与检查路径的既有边界一致。

## 追加（2026-09-30）：跑项目自带命令的检查要在项目旁边跑，不能在工作副本里跑

**实测（形状 A 复跑，任务 68543fed 的「在集成副本上跑整套测试」门）**：同一提交、同一命令、同一份依赖，只换位置/形态——

| 位置 | `node --run check` |
|---|---|
| 宿主状态目录下的工作副本（`state/worktrees/<task>/integration`） | **127 failed / 1480** |
| 项目根旁边的副本（`<项目根的父目录>/.graph-check-…`） | **1480 passed** |

两个原因，都指向「本项目的测试套件不是位置无关的」：

1. **依赖是软链，而沙箱要求授权路径已经是规范形式。** 决策 1 让副本里的 `node_modules` 成为软链；`restricted-process` 的 `canonicalGrant` 拒绝一切 `realpath(path) !== path` 的授权路径（这条守卫是有意的：worker 能在自己的副本里造软链，若连读授权都跟着解析，边界就被绕过）。于是套件里那些把 `resolve('node_modules')` 当 `readPaths` 交给沙箱的用例一律抛错、沙箱内进程起不来——**一个变量就能复现**：同一目录下把软链换成硬链，6 个失败变 6 个通过。
2. **套件要读项目根旁边的同级仓库。** `tests/m7` 从 `process.cwd()/../12-MediaBookmarks` 取文件，状态目录下没有那个同级目录。

**决策**：`graph.command` 新增可选 `copy: "project"`。声明后，该检查在一个**建在项目根旁边的新 worktree** 里跑，并把项目的唯一一份安装**硬链**进去（硬链是副本内的普通文件，授权路径因此规范，且仍然共享同一份磁盘块）。副本以「做它时的那次提交」为键：提交没变就复用，变了一律重建，绝不拿旧提交跑新检查。检查自己的证据仍写在 scratch 目录，不写进副本。

**为什么不是改工作副本的位置**：工作副本在状态目录下是准入与隔离逻辑的前提（`git-admission` 等测试钉着它），而副本位置只影响「项目自带命令能不能跑」。**为什么不是让 `canonicalGrant` 跟着解析软链**：那会放行 worker 自造软链指向的外部读取，正是这条守卫要拦的。

**未解决**：软链与硬链两种形态下，对 `node_modules` 的写入都靠沙箱按字面路径授权，都可能穿透到共享安装；这不是本条引入的回退，但记在这里以免被当成已解决。
