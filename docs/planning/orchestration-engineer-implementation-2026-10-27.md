## 方法

逐单元实施并验证，源码与测试在运行期间冻结。底层持久化和身份改动由主线程串行拥有，测试可按独立文件委派。只有真正E2E可以新增或修改。验证以真实HTTP、daemon、SQLite、PiG、Git与浏览器为准。

审计日志见 [决策记录](orchestration-engineer-decisions.tsv)。当前未启动用户数据库迁移，不自动选择已有多个会话中的某一个。

节点问题已记录但进程在停放前中断时，恢复逻辑保留原输入并把问题交给项目主管，附带中断原因和待核对的模型调用；调用未结算时不接受答复。禁止绕过未解决的问题直接恢复或变更队列。仍需以真实进程中断验证此路径和未知模型调用费用的核查与恢复；目前不能视为 D3 的完整重启恢复。

真实模型接口不返回用量字段时，适配器会记录估算用量；已验证此情况下节点提问、主管答复和原执行继续运行。这不等同于进程中断后调用状态未知的场景。

已通过真实端到端场景验证节点问题经项目主管、全局主管升级给用户，再由两级主管逐级返回并恢复节点执行。

已通过强制终止进程验证已停放的节点问题及原执行可恢复，并修复重启后误用提问前回执的问题。项目主管自身的未确定调用现在交由全局主管核查；重试需要记录核查理由，问题也可升级给用户。已分别验证全局主管核查后重试，以及向用户澄清、收到答复后核查重试的路径。

独立 graph、工作级暂停和任务控制的主管恢复入口现在要求引用解除归档之后、当前主管轮次中真实用户消息的原话；端到端验证项目主管与全局主管无来源的自行恢复被拒绝，用户明确指令可以恢复。来源校验不替代主管对用户原话含义的判断。

旧草稿确认工具也要求引用当前主管轮次中实际用户消息的文字，交接消息或编造的文字不能作为来源。真实模型工具调用测试验证了无来源确认被拒绝、用户确认后可以创建 graph；来源校验仍不替代对原话含义的判断。

项目主管可对正在运行的 graph 节点发出即时引导：中断当前模型响应并在同一执行中继续，重复请求沿用原执行与回执。也可停止指定节点并暂停其队列；端到端验证另一并行节点继续运行、重复停止不会产生第二条请求，停止后强制重启不会自动重新执行。停止信号未送达时保留暂停并允许重试。引导和停止动作执行过程中的进程中断、以及未知调用核查后的恢复仍需独立验证。

用户可以在节点对话中直接即时引导或停止节点；浏览器端到端测试验证了两种操作。对正在调用模型的节点强制终止进程后，真实 HTTP 测试验证了未知用量会阻止恢复和重试、核对可幂等且本身不解除暂停；明确重试后保留原记录并以新执行继续。

D5 的迁移范围完成：未完成 graph 现可在选择主管时事务性转交，保留原始会话来源；真实迁移测试验证了负责人、历史、未消费的节点失败通知、重启后的管理列表，以及节点后续向新主管提问并继续。待处理的节点消息及对应通知也可转交，原消息保留在历史中，测试覆盖了投递和重启后的去重。未暂停且未归档的旧会话中待处理的普通消息会按顺序作为历史交接转交，保留来源和附件，不被视作新用户授权；真实重启测试验证了进入主管上下文，暂停会话则仍阻止切换。准备中和失败的建图也能转交：同一进程中的准备按 graph 串行接续；重启后结果不确定时先要求核查 Git 进程与工作副本，记录理由后才重试，保留原 graph 和创建请求。非 graph 的旧工作及无法归属的通知不在 D5 范围：它们仍阻止切换，作为显式安全边界而不是静默转交或删除。

多个旧会话的主管选择现有只读迁移预览，逐个展示待转交 graph、节点消息、通知与已知阻碍，确认时仍在事务内重新检查。真实浏览器测试覆盖查看、取消和确认；真实 HTTP 测试覆盖预览未修改会话及其与 graph 转交的关系。通知是否可安全归属仍要在提交时核查，预览不保证切换一定成功。

转交后的 graph 同时保留在来源历史对话的任务列表和事件中；新主管仍按正式 owner 管理。真实迁移测试检查了两个视图、历史事件及重启后的来源视图。

选择主管与调度准入使用同一互斥边界；准备中、已派发或结果未知的旧主管轮次会阻止切换。历史会话不会在启动恢复时创建主管，也不会被调度。真实 HTTP 并发测试验证了切换时接受的消息恰好转交一次，切换后的消息被拒绝；重启测试确认历史主管没有被创建或执行。

另以真实运行中的主管验证切换：模型响应未结束时预览显示活动轮次且选择被拒绝，响应结束后原对话可转为历史。委派和多 graph 并行的现有真实端到端场景与迁移测试一同回归通过。

已结束的 graph 若仍有未消费通知，迁移会一并转交其主管归属，使接收通知的新主管能够读取结果；不属于旧主管的通知则拒绝转交。真实模型工具调用测试验证了停止通知、主管读取及来源历史保留。

真实 Git 测试覆盖了准备中转交、准备失败、转交与失败并发，以及强制重启后的人工核查；均验证原创建请求与 graph ID 保留，最终只有一个工作副本。项目归档或工作暂停会阻止新一轮准备准入。

工作草稿确认触发的 Git 准备现在也在进程中断后等待核查，不再自动重放未知外部操作。真实 Git 进程强制中断测试验证重启不重复创建、无核查理由的重试被拒绝，核查后重试成功并更新原工作 graph 的状态。

准备失败后的重试会先持久化为准备中；真实 Git 测试验证重试过程中再次强制终止后，重启重新要求核查，随后仍复用原 graph 与工作副本。

相同建图请求的普通重放不会重试失败的 Git 准备；真实测试验证保留原 graph 和阻塞回执，直到显式核查并请求重试。

相同主管和请求 ID 的并发建图已串行受理；真实 HTTP 测试验证并发请求返回同一 graph，历史会话不能在迁移事务后新建 graph。原 Git 失败验收已同步改为显式核查后重试。

迁移消息和准备重试的状态写入已收回各自表的存储所有者；表所有权检查与真实迁移、Git 恢复、归档测试通过。当前变更中的源码文件均未超过 500 行。

真实 HTTP 竞态测试覆盖建图与主管切换同时发生：已接受的 graph 归新主管，切换后的历史会话建图被拒绝；相同请求 ID 不同内容仍被拒绝。

## 2026-10-28 接手与收尾

Codex 会话在完整检查运行到一半时结束。接手后按会话记录、设计、决策表与工作区实际状态恢复，不重跑已完成的单元。

- 首轮完整 `node --run check` 在 `go-wake-notification` 处失败。3 个并发单文件复现 2 次失败，确认是停驻输入恢复时 `attempt` 计数在进程中断窗口内的竞态，不是新的执行或重放：同一执行、同一 submission、`retries_used` 不变、模型请求仍只有一次且使用冻结配置。断言改为比较执行身份、submission 与重试额度，并保留该执行 `attempt` 为 1 或 2 的界；修复后 3 个并发复跑全过。
- 默认应用验收补在真实 Electron 窗口：`tests/e2e/desktop-shell.test.ts` 新增用例验证默认窗口提供全局主管入口、标题与 `projects: []` 的初始状态。该层与浏览器 E2E 是不同生命周期边界，不替代浏览器用例。
- 完整检查随后在 `harness-tool-schema` 处失败：默认入口变为全局主管后，工具描述从旧会话的 50 个工具、7,485 字符增至 56 个工具、9,436 字符（新增 `ask_user`、`control_task` 与工作工具）。测试改为测量全局主管入口，预算随范围从 7,500 上调到 9,700，并增加每工具均值不超过 175 字符的第二道约束；当前 9,436 字符、均值 168.5 通过。
- 2026-10-27 删除了两条旧 UI 用例（项目分组侧栏、新建会话模型切换）。其契约已由 `orchestration-browser.test.ts` 承接：项目/最近折叠、可访问名称、焦点、侧栏收起、无概览/向导入口、模型选择与最终会话模型。删除依据记录在此，避免把“旧文件不见了”当作覆盖率事实。
