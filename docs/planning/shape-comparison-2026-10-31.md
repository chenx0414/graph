# 三个真实任务的图形状对照（2026-10-31）

同一台机器、同一个模型（`opencode-go:deepseek-v4.1-flash`）、同一份 R15 规则（"先选形状，再写节点"），
三个任务各自派生一个独立的 main Agent 会话，**没有任何人工指定形状**。下面是它们各自提出的草案。

## 任务与形状

| | 任务 | 节点数 | 形状 | 模块 | 边 |
|---|---|---|---|---|---|
| **A** | 单点修复：`index.html` 加 `Cache-Control: no-store` + 一条 E2E | 2 | `work → review`（串行） | `check`（宿主命令） | 0 |
| **B** | 多文件：把 `ruleSeedGaps` 做成 Agent 上下文抽屉里的可见信号（前端组件 + CSS + E2E） | 2 | `work → review`（串行） | `checks`（宿主命令） | 0 |
| **C** | 方案比选：缓存策略三选一，给出可复核推荐 | 6 | `measure → {no_store, versioned_refs, server_cache} → rank → recommend` | `deliverable_check`（宿主命令） | 9 |

## 它们各自怎么回答 R15 的三问

**A（单点）**
- 能并行吗：几乎不能，修复与"证明它修好的 E2E"改的是同一个行为（`serveHome` 的响应头），并行只会互相等。
- 要候选吗：不要，不用 jury。正确结果由需求钉死，没有可排名的设计空间。
- 哪一步不可逆：`complete` 会把提交合入 main 并让运行中的 daemon 对外返回新头，人在那一步之前确认。

**B（多文件）**
- 能并行吗：实现是一条耦合车道（组件 + 类型 + CSS + 测试共享同一处契约）；`check` 与 `review` 可以同时派发，但都不接自动边，因为 operation 模块记录的是派发前的 HEAD，自动边会在宿主集成之前就跑检查。
- 要候选吗：不需要。位置与文案沿用仓库既有模式，硬约束是需求给定的文案与既有布局不变量。
- 哪一步不可逆：合并进目标分支/交付（`complete` 触发 Git 交付）。

**C（比选）**
- 能并行吗：三条评估车道互不依赖，各自只读同一份证据基线，所以 `measure` 之后扇出、由 `rank` 的三个具名输入汇合。`measure` 必须排在前面，否则三条车道各测量一次，代价三倍且数字会互相矛盾。
- 要候选吗：**不用 jury，并给出反证条件**——候选是设计而不是可再测的产物；硬性条件与权重在结果出现前冻结在定义里；若评估矛盾到打分表无法复算，就在同一张图补 jury，而不是让 rank 凭印象定。
- 哪一步不可逆：图内没有不可逆步骤（只写备忘与一条后续任务），所以人工验收放在图末作交接点，**而不是在图中间加 `human_check` 把流程挡在用户回答上**。

## 它还做了实测（不是纸上推演）

C 在提交草案前用真浏览器做了对照组实验：

- (a) 同一 URL 再次导航 → 拿到新构建；
- (b) 导航到别的 URL 再回退 → 页面显示 `BUILD 3`，服务器已在发 `BUILD 4`，回退没有产生新请求；
- (c) 对照组同一形状的响应加 `Cache-Control: no-store` → 回退重新向服务器取（服务器日志出现新请求）。

这三条把"重载后用旧 bundle"从怀疑变成可复现机制，也解释了为什么 A 与 C 的结论不冲突。

## 结论

1. **A 与 B 形状相同，而且是对的**：两个都是"改这个仓库的一小部分"，最小正确形状就是 `work + review`。趋同在这里不是缺陷。
2. **C 完全不同，而且不同得有理由**：任务本身有"三份互不可见的独立评估"，形状才长出扇出 + 具名汇合 + 排名。
3. 所以上一轮"形状高度集中"的观察，主要解释是**任务同质**，不是能力缺失。真正被判死的是"有没有被要求解释"——R15 让三个任务的差异从"凭感觉"变成"写在 decisions 里的可核对理由"。
4. **shapeNotes 确实到达并起了作用**：A 明说"shapeNotes 点的'未连线'即此设计选择"，并指向 `docs/agent/code-delivery.md` 的显式投递形状，而不是无视它。

## 局限（别把它当定论）

- 每个任务只跑了一次，没有重复性检验；换模型或换一天，形状可能不同。
- 三个任务仍然都在同一个仓库、同一类工程语境里；非工程任务（写作、数据分析）没有测。
- 成本：C 花了约 35 分钟、122 条消息的真实调查（含浏览器实验），A/B 各约 4–5 分钟。
