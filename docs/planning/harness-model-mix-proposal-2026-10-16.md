# 下一阶段提案：隔离评测现有免费 worker，不修改默认路由

现状：两项静态上下文实验在单个真实 parser 任务中都没有降低任务总成本。未缓存输入下降不一定抵消额外请求与输出。当前工程修改、实验结果和证据在 [主报告](harness-token-efficiency-2026-10-16.md)。这份文件仅是提案，尚未实现模型路由、改变模型或 effort 默认值。

目标文件把模型、路由、effort 和 Agent 分工明确限定为 propose only。因此下一阶段先由使用者决定是否进行以下隔离评测；本提案不授权生产启用。

## 具体候选

保留现有 main 和 `opencode-go:deepseek-v4.1-flash`。在独立新会话评测已配置的 `opencode-go:longcat-2.5-preview-free` 作为边界明确的 worker；不在已有对话中切换模型，不改变独立审查的模型排除规则，不改变测试与权限约束。父 Agent 继续负责目标、集成与结果核验；候选只处理冻结的输入和自己的工作副本。

官方 [OpenCode Go](https://dev.opencode.ai/v2/docs/console/go/) 当前把该预览模型列为免费且限时。评测前重新核对可用性与价格；不能把临时免费解释为长期成本保证。若模型不可用，报告失败；不在后台换模型掩盖候选失败。

## 固定任务与验收

开始前保存相同仓库快照、原话、初始文件、验收命令与配置，固定以下类别；每类三次独立重复，顺序采用 ABBA/BAAB 交替，cold/warm 分组记录。先做公开行为验证与小规模可行性检查，再决定是否支付扩大样本的时间成本。

| 类别 | 原话形态 | 质量证据 |
| --- | --- | --- |
| 配置解析修复 | 空行别当配置，值里的等号保留 | CLI 验证值、键数量、原有正常输入 |
| CLI 参数 | 加 count 参数，默认别变 | 实际 CLI 默认、显式值、非法值退出码 |
| 持久状态修复 | 重启后也要保留结果 | 真实应用运行、磁盘写入与重启后的读取 |
| graph 定义/投递 | 建两步流程并传结果 | 正式 graph API、协议校验、投递与结果 |
| artifact 使用 | 分析指定已发布版本 | 正式发布/读取，版本与 digest 一致 |
| 模块命令失败处理 | 跑检查，修配置，不改检查程序 | 真命令退出码、检查程序字节不变 |
| 续跑/返工 | 只修指出的问题 | 同实例历史、累计用量、未授权文件不变 |
| 代码审查 | 按验收检查这份改动 | 冻结版本、真实缺陷发现、证据和独立性 |

任务输入必须短且接近真实使用，不能给候选额外解题步骤。只替代外部服务的受控 E2E 先证明 harness 生命周期，随后使用真实模型。复杂 UI、凭据变更、最终合并、发布和安全敏感动作不纳入首轮候选执行范围。

## 完整成本与门槛

成本包含 main 的计划、worker 全部请求、工具往返、重试、补交、压缩、交接、核验与返工，不只比较 worker 单价。每调用冻结价格、usageSource、四种计费 token、模型和任务归属；价格缺失则该任务成本保持未知，不填零。

独立会话的单 worker 对照只能证明 worker 可行性，不能宣称 whole-tree 节省。通过后才提出默认关闭的 planner+worker 原型，并重新测整个任务树。这个原型也属于 Agent 分工变更，需明确接受后再实施。

成功条件预先固定：候选不能比 baseline 多出验收失败、权限突破、证据虚构或独立性违规；固定集的任务总价格加权成本应下降且置信区间支持该结论。继续报告时延、总轮次、工具错误、cache hit 与代码存留；样本不足、质量下降、成本不降或调度开销抵消收益，均记录为不通过，不扩大上线范围。

## 回滚与决策

评测只写独立临时项目和状态库，保留原始报告；不修改现有会话、默认模型、用户工作副本或生产路由。任何后续候选都必须默认关闭，可通过撤销候选配置回到原模型。

待使用者决定：是否接受上述现有模型的隔离评测范围。即使接受评测，也不等同于接受路由、effort 或 Agent 分工的生产变更。
