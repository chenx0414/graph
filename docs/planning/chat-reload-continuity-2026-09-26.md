# 聊天重载连续性与长历史加载

基线：产品线 `67162fe`。实现位于独立分支 `codex/chat-reload-continuity`；开发与验证不修改运行中 App 的 checkout、生产数据库或 Main Agent 会话，不触发重载。

## 已复现的问题

- SSE 每次挂载从游标 0 开始；会话快照与旧 delta 重放同时进入投影。回归测试复现已显示文本从 `done` 倒退到 `do`，以及消失的流未从快照对账中删除。
- RSI 在请求重载时提前写回复标记；`recordConversationOutput` 因标记直接返回，丢弃真正结算的过程记录。回归测试得到空 activity，而不是重载前的叙述。
- 过程只存在 worker 内存，重载前未及时保存。没有 ordinal 的历史过程遇到 live tail 时也会被渲染器漏掉。
- 桌面重载只加载新的服务地址，丢掉 hash 路由。端口变化使浏览器按 origin 存储的状态无法承担跨重启恢复。
- 每条回答单独扫描全部历史计算时长，生成行的开销随消息数平方增长；历史翻页还会重新计算整个会话详情。

## 实现

- 会话快照携带同一同步读取段的事件游标；初次 SSE 从该位置接续。分别维护已处理事件游标与快照游标，避免晚到的快照覆盖新流，或跳过已经加载的旧消息更新。
- 快照对账清除不存在的流；使用 operation + ordinal 排除已经持久化的叙述。既有快照文本立即显示，新到文本继续渐进揭示。
- 工具开始前与结束时检查点保存叙述和工具状态；使用稳定键更新已有记录。回执不再阻止过程结算。并行工具分别保持进行中状态。
- 展示层通过 `rsi_continuations` 的父子 operation 关系组织同一轮，隐藏独立重载回执；执行 operation 及预算不合并。过程和 RSI 卡片保留可展开查看，确认激活的卡片默认收起。
- 桌面进程保存允许的内部路由，启动与重载使用新端口加原路由；不持久化完整 URL。
- 页头显示 Main 的工作动画，加载会话显示 spinner，并遵从 reduced-motion 设置。
- 历史按页读取独立轻量接口；初次仍只取最近 200 条。生成行采用单次扫描计算时长；离屏历史使用浏览器 content-visibility 跳过布局。delta 不触发完整视图重查。

## 验证

- 最初两项回归：2 failed / 17 passed；修复后通过。
- 浏览器使用临时 SQLite，写入 1,000 条旧 delta 后打开及刷新会话：订阅游标大于 1,000，旧气泡不出现，既有叙述只有一份，当前流保持显示。
- 浏览器覆盖历史翻页、稀疏序号、突发消息、会话切换、加载后的旧消息更新；保留新 chunk 渐进揭示与 RSI 卡片展开回归。
- 纯逻辑测试覆盖重载前后一个过程组与最终回答、无 ordinal 历史不丢失、快照/事件竞态、回执之后过程保存及幂等、桌面端口切换恢复。
- 10,000 条合成消息的行生成基准，初次测量从约 61 ms 降到 5 ms；仅衡量投影生成，不代表真实 App 总加载耗时。
- 最终 `node --run check`：162 个文件、1,187 项测试全部通过；类型检查、异步断言检查和验收证据检查通过。日志：`/tmp/graph-chat-continuity-final.log`，退出码 0。
- 全量回归曾发现离屏布局优化影响节点聊天弹窗，已将选择器限定到主会话历史；节点详情回归恢复通过。
- 开发期间产品线推进至 `2b8353e`，新增提交没有改动本分支涉及的文件；未直接集成或部署。

## 生效与边界

本分支没有合入正在使用的产品线，也没有重启 App。需要在 Main 的安全空闲点集成并正常重载；不能把分支测试通过当成生产窗口验收。

此修复防止后续重载丢失记录，不伪造已经未保存的历史过程，也不回填生产数据库。后台 activation 仍只表示宿主确认，不能单独证明窗口已恢复。
