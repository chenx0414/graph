## Owner/caller evidence

Public graphCreate → GraphRuntime + KernelStore admission; public graphSend → kernel.deliverDirect → durable kernel_module_inbox; host GraphRunner consumes inbox in delivery.seq order, ModuleRuntime judgment+processed flag commit together; committed transition outbox broadcasts after crashes. graphControl reopen → reopenAfterPending serialization. graphInspect module/module_values/module_transition exposes held inputs, latch, transitions, versions/reasons; graphInspect edge exposes delivered values/source/sequence.

GraphRunner calls routeModuleOutputs with queueOnly=true both for recovery outbox and current judgments. It never uses recursive module evaluation: next module runs via durable inbox next pass. Direct recursive branch is exercised only by isolated helper tests; MAX_ROUTING_DEPTH cannot honestly be claimed a live E2E contract. Public module cycles require a bounded business guard/once latch to terminate; an unguarded each→each cycle is potentially infinite work and should not be added merely to manufacture R5 proof.

Parser validates shape/rule nonempty/declared emit ports at creation but does NOT parse rule syntax or detect duplicate output claims there. Invalid expression, duplicate rule output, and once multi-input missing requiredInputs fail when real delivery runs, pause the module, preserve input/inbox, report graph.module.failed. Migration must exercise runtime failure rather than incorrectly demand graphCreate rejection.
