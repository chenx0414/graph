结论：按节清单实验仍关闭。不能把一个 parser 样本的 500 字节模型节或工具错误解释成真实人群效果。历史库中清单工具覆盖约 35.3% 的有工具活动 main 会话；完整结果也确实较大，值得继续验证按需读取。但现有数据没有新选择器采用率、逐请求来源/缓存归因和完整价格，不能证明每完成任务成本下降。

## 会话结果与副本核对

通过正式 end 事件的 operationId 关联 operations.instance_id，读取这 36 个实例的 45 份真实 Pi JSONL（约 746.5 MB，流式扫描；不导出用户正文/凭据）。原始找到 126 条对应 toolResult，不能直接称为 126 个 API/工具调用。

本批 55 个权威 end 事件中 instance+toolCallId 恰好唯一；只有在验证这个条件后才用于这批对账，不把它推广成通用去重规则（供应商可能重用 call ID）。54 个事件找到会话结果；重复副本 text SHA-256 全一致，记录时间与对应 end 事件相差最多 70 ms，没有冲突正文。另 1 个缺失正文明确保留未知。

54 个匹配结果中：1 个 isError，9 个成功结果非完整 JSON（可能已有落盘/摘要），44 个是可解析的完整库存 JSON。44 份完整正文累计 1,199,585 UTF-8 字节，中位 26,802、最小 24,524、最大 33,839。仅对这 44 份完整 JSON 作 configuredModels 整节投影，正文中位 776、最小 776、最大 1,482 字节。数据结构在历史间演进，不把这些值当成当前 API 固定大小，也不把投影当成模型实际选择了该节。

单样本报告的完整正文 28,436 / 模型节 500 字节仍是那个私有 parser A 配置的观测，不能替代本次人群分布。原始 126 条正文累计 3,577,868 字节包含分支副本，不能用作历史实际发送总量；即使去除副本，响应写入一次也不等于后续真实请求中被重发多少次。

## 对机会排序的影响

这项是响应检索实验，不是按“极低频”删除静态工具。新 schema 在真实 wire 增加 517 字节；未知多少实际请求含该工具、已有内容被缓存/压缩/重发多少次，以及哪些查询需要完整清单。因此不能用 55 次响应缩小量减去全库请求数乘 517，冒充价格加权收益。

后续评测必须包括需要模型/配方清单的完整任务与不读取清单的常规编码任务，保留完整成功条件、静态前缀代价、额外发现调用、失败和未知费用。仅检查某一节是否变短不能支持启用；只完成目录查询也不能替代原编码任务或整棵 graph 交付。此前 Step 5 基础阶段已停止，不补跑、不改变完成定义。
