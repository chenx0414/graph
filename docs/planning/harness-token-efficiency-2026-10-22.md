# Graph harness 价格加权成本：2026-10-22

分支 `feature/harness-token-efficiency-2026-10-22`（基于 `main` 的 `adb6396`）。
本轮目标：降低**每个完成任务**的价格加权成本，质量不下降。

本报告分五篇：**[基线](harness-token-efficiency-2026-10-22-baseline.md)**（量到什么）· **[已做的修改](harness-token-efficiency-2026-10-22-changes.md)**（做了什么、怎么验证）· **[真实模型 A/B](harness-token-efficiency-2026-10-22-ab.md)**（command-goat 免费模型上量到的与量不到的）· **[提案与缺口](harness-token-efficiency-2026-10-22-proposals.md)**（只提案的那部分与还欠着的部分）。

结论摘要：

1. 上一轮审计（`harness-token-efficiency-2026-10-16.md`）写的是已退役的 TypeScript 侧车。**live 路径已经换成 Go + PiG 内核，静态上下文不再是主要开销，话上下文的大小才是。**
2. 基线（真实库只读快照）：19,608 次请求、129 个 task、4,432,477,135 个缓存读取 token。缓存读取占 token 总量 96.8%，按计费类型折算后占花费 **42.7%**；未缓存输入 36.1%，输出 21.2%。
3. **每一次请求携带的前缀平均 246,440 个 token**（中位 235,497，p90 450,048，max 673,408）。这是最大的单一开销来源，而它的大小完全由**压缩阈值**决定：会话在到达供应商窗口前才压缩，实测压缩前中位 495,979 token、压缩后中位 27,158 token。
4. 静态前缀（系统提示 + 工具声明）在主会话里约 15,701 token，只占平均前缀的 **6.4%**。这解释了前一周工具卸载实验为什么没有降本（浏览器按需加载反而贵 39%，目录工具按需加载贵 3.35%）：在 246K 的前缀里省 2K token 是 0.8%。
5. 已提交 6 个独立可回滚的修改：助手回合如实回放（reasoning + tool_use）、Anthropic 传输显式缓存断点、可由环境变量命名的压缩上限、摘要拿到它自己要的输出预算、任务说明包不重复发送、成本 CLI 增加前缀/用途/整树情景计价。
6. 压缩失败的根因也找到了：请求自己的输出预算在内核桥上被丢掉，摘要被按模型的整个上限要（生产模型 384,000），于是摘要写到被切断为止——9 次失败里 6 次是这个原因，而失败的压缩会把 496K 的上下文留在会话里。
7. **会话上下文的第二块重复**：任务说明包在每次 operation 里重发同一段环境说明（实测 62 份里 89.5% 逐字相同，占 transcript 20%）。已做成默认关闭的 `GRAPH_REUSE_TASK_SETUP`，去掉重复约等于上下文 −18%。

**真实模型 A/B 跑了**（command-goat 免费模型、Go 后端、独立行为检查、22 次通过检查的运行；另有 parser、command、长会话三组共 30+ 次运行）。

**最重要的一条结论不是哪个改动省了钱，而是"省前缀"在什么负载上才值钱**：一个前缀缩减值多少，取决于**缓存读取占这次任务花费的比例**——短任务（上下文 12K）里缓存读取只占 8%，生产会话（上下文 246K）里占 42.7%。**同样的前缀缩减，在短任务上不值钱，在生产会话上值 5 倍。** 所以这个任务集上三个杠杆全都测不出差别（接缝：花费差 −1.7%，t=−0.10；说明包复用：长会话里缓存读取 −17.6% 但花费平；压缩上限：根本不触发）。

站得住的是：接缝的**机制**（真实输出 78,934 字符 → 模型读 19,959 + 句柄，句柄逐字节齐全）、说明包复用的**前缀缩减**（−17.6%，实测）、以及按生产负载形状代进去的**价值排序**（上限 −29% > 说明包 −7.6% > 接缝 −2.2%）。

**长会话（21 轮）把排序改了**：接缝和压缩上限是**替代关系**——接缝把大输出压住，上下文就不再逼近窗口，32K 的上限一次都没触发；任务说明包复用让缓存读取 −17.6%，但总花费是平的。

**尚未证明**："每完成任务成本下降且质量不降"——三个杠杆在短任务上**都测不出钱**（接缝 n=11：花费差 −1.7%，t=−0.10；说明包复用：长会话里缓存读取 −17.6% 但花费平；压缩上限：根本不触发）。**原因不是改动没用，而是短任务里缓存读取只占花费的 8%，生产会话里占 42.7%**——省前缀在短任务上不值钱，在生产会话上值 5 倍。站得住的是机制、字节和方向，不是账单。

## 1. Harness 地图（当前 live 路径）

生产桌面应用运行的是 Go 二进制 `dist/graphd`（`desktop/main.mjs:27`），不是 `src/server/cli.ts`。

| 层 | 权威实现 | 现状 |
| --- | --- | --- |
| 会话内核 | `backend/internal/graph/runtime_pig_session.go:45` → `pigkernel.OpenSession` | PiG（Go）承载主 Agent 会话、崩溃恢复与图节点泳道；TypeScript durable 侧车已退役 |
| 提示词拼装 | `backend/internal/graph/runtime_pig_instructions.go:22` | Graph 提示词 → `<project_context>` → `<available_skills>` → `<cwd>`，四块顺序固定 |
| 系统提示 | `backend/internal/graph/runtime_agent_system_prompt.go:103` | identity → rules → docs；逐块可审计 |
| 能力库装配 | `backend/internal/graph/runtime_agent_context_assembly.go:364` | 工具按名字排序（`runtime_capability_bundle.go:329`），确定性 |
| 工具定义 | `backend/internal/graph/runtime_agent_tool_definitions.go:197` | 46 个 Graph 声明；另有 Pi 原生工具、codemode、扩展工具、PiG 原生 MCP 工具 |
| 请求装配 | `backend/internal/graph/runtime_controlled_openai.go:690` | **daemon 自己拼 wire body**；PiG 的 HTTP 层被绕过 |
| 压缩 | `backend/internal/graph/runtime_compaction.go:91` | daemon 自己判断；内核侧的阈值被显式关闭（`backend/internal/pigkernel/resident.go:69`） |
| 用量记账 | `backend/internal/graph/runtime_kernel_provider_gate.go:115` | 缺用量记 unknown，不记零；调用时冻结价格 |
| 计量 | `scripts/harness-cost.mjs` | 只读快照；本轮扩展 |

### 两个必须知道的边界

- **主 Agent 会话在 Go 内核上，开发者/CLI 路径（`src/server/`）在 TypeScript SDK 上。** 两者共用同一个 `tasks.sqlite`，但提示词拼装与请求装配各有一份。本轮的 Go 修改只覆盖生产路径；`src/runtime/compaction.ts` 的同名修改保持两边一致。
- **压缩是 daemon 驱动的，内核自己的阈值是关的**（`resident.go:69`：`Enabled: false, ReserveTokens: 1024, BackgroundTokens: 0`）。所以阈值改一处即可覆盖主会话。

## 3. 机会排序

排序依据 = 花费份额 × 可移除比例 ÷ 质量风险。可移除比例来自上面的账本，不是来自外部团队的百分比。

| 优先 | 层/候选 | 估算与依据 | 质量风险 | 验证 | 回滚 |
| --- | --- | --- | --- | --- | --- |
| 1 | **压缩阈值（会话上下文上限）** | 前缀均值随阈值线性缩放。阈值 128K → 缓存读取 −68.5% → 整树情景花费 −29.3%（$28.44 → $20.11）。**前提是上下文能长到 496K**——接缝开着时 21 轮会话的 32K 上限一次都没触发，所以这条仍是推演 | 中：摘要更早替换，模型可回看的原始历史更少 | 长会话 A/B（§5.4） | 去掉环境变量 |
| 2 | **任务说明包复用（占 transcript 20%）** | 长会话（21 轮）实测：缓存读取 **−17.6%**，与"去掉 20 份重复说明"吻合；质量 21/21 全过。生产规模价值 ≈ −17.6% × 42.7% ≈ **−7.6%** | 中：模型读到的环境说明变远、变少 | E2E + 长会话 A/B（§5.4） | 去掉环境变量 |
| 3 | **工具结果接缝（Go 侧从未接线）** | 生产历史：工具结果字节 −10.5% → 前缀 −5.2% → 生产规模 ≈ **−2.2%**。端到端花费在短任务上**测不出来**（n=11：花费差 −1.7%，t=−0.10；中位反号）。机制是确凿的：真实输出 78,934 字符 → 模型读 19,959 + 句柄，句柄逐字节齐全 | 低：只改形状不丢数据 | E2E（§4.7）+ A/B（§5.2） | `GRAPH_TOOL_RESULT_SEAM=0` |
| 4 | **压缩失败（9 次，6 次撞 token 上限）** | 根因已定位并修复：请求自己的输出预算被桥丢掉，摘要被按模型的整个上限要。失败一次 = 上下文停在 496K = 之后每个请求重付整段前缀 | 中：请求形状变化，需 PiG 支持 | E2E 已覆盖（`129da7e`） | revert 该提交 |
| 5 | **压缩调用的输入未命中缓存** | 20.4M 未缓存输入按 50×缓存价计价，$0.73 情景花费；让摘要请求复用会话前缀可把它变成缓存读取 | 中：请求形状变化，需 PiG 支持 | 同上 | 改回 |
| 6 | **工具声明（46.9K 字符）** | 只占平均前缀 6.4%。全砍一半 → 缓存读取 −3.2% → 整树 −1.4% | 中高：模型可能需要首轮发现 | 前一周两个实验已证伪（浏览器 +39%、目录 +3.35%） | 已有 flag |
| 7 | **大输出落盘（bash 占上下文 35%）** | 超过 2,000 字符的结果只有 18 条（占工具结果字节 22.6%）→ 上下文约 −8%；ANSI 与行号前缀只占 0.8% | 中：模型要多读一次文件 | 需要真实 E2E（工具结果形状变了） | 独立 flag |
| 8 | `<available_skills>`（8,035 字符） | 系统提示最大块，但只占前缀 0.8% | 中：技能发现变难 | 同 6 | 改回 |
| 9 | 反复工具错误（edit 9.0%、artifact_publish 9.1%、graph_patch 28.6%） | 每次错误至少多一轮；188 条记录里 86% 是预期的，7% 是 harness 缺陷（§2.7） | 低 | 真实 E2E | 独立提交 |
| 10 | 模型、路由、effort、分工 | 前一周的隔离对照没跑完；目标书明确要求只提案 | 高 | 提案 | 只提案 |

**结论：第 6、7、8 项（前一周的重点）在当前阈值下没有杠杆。** 静态前缀只有 6.4%，把它砍掉一半也只值 1.4%。如果先降阈值（把平均前缀压到 77.6K），静态前缀占比升到 20.2%，工具裁剪才值得做。**顺序很重要。**

**而"省前缀值多少钱"取决于负载形状**（§5.2）：短任务里缓存读取只占花费的 8%，生产会话里占 42.7%。**同一份改动在短任务上省不出钱，在生产会话上值 5 倍。** 任何后续对照都必须挑对负载，否则测的是噪声。

## 10. 验证

**完整门禁**：`node --run check` 在 `feature/harness-token-efficiency-2026-10-22` 上跑通——**291 个测试文件 / 1,558 项测试，288 文件通过、1 个跳过（浏览器环境依赖），1,555 项通过、3 项跳过，退出码 0，验收证据未变**（2026-10-22 22:12 那轮，无并发改动）。

**另一轮（22:40）红了 96 项 / 39 个文件，原因是机器被压垮**：那一轮耗了 1,467 秒（平时 200–350 秒），当时另一个会话同时在跑它自己的整轮门禁，机器上有 47–49 个 vitest 进程、可用内存 384MB、swap 已用 3.9GB。**39 个失败文件里没有一个是本分支新增的测试**；抽 6 个失败文件隔离重跑，30 项全过。类型检查、lint、验收证据检查单独重跑也都通过。

**真实模型 A/B**（§5）：command-goat 免费模型，Go 后端，独立行为检查，四组共 30+ 次运行。接缝开/关各 11 轮 big-output 任务，**花费差 −1.7%（t=−0.10，测不出）、质量 22/22 全过**；两个 flag 在短任务上是 null 结果，8,192 的激进上限是负结果；21 轮长会话里说明包复用让缓存读取 −17.6%。

**每个修改都做过红灯验证**（把生产改动撤掉，E2E 必须红）：

| 提交 | 红灯证据 |
| --- | --- |
| `6b2eca8` 助手回合回放 | 撤掉后 OpenAI 与 Anthropic 两条 E2E 都红（reasoning 不在下一轮请求里）；只撤掉"工具块索引"这一处，两条 reasoning 断言同样红 |
| `e18a65b` 缓存断点 | 撤掉后 Anthropic E2E 的三个断点断言红 |
| `ff7b6da` 压缩上限 | 撤掉后"设了上限就压缩"那条红，"没设上限不压缩"那条始终绿 |
| `129da7e` 摘要输出预算 | 撤掉后摘要请求带的是模型整个上限（8192 而不是它自己的额度） |
| `2037c4c` 任务说明包复用 | 打断复用逻辑后"开启开关"那条 E2E 红，"关闭开关"那条始终绿 |

**没有做**：真实模型的 A/B。压缩上限默认关闭，本轮交付的是可测量的机制、账本上的基线和一条按真实账本推演的收益，不是"每完成任务成本已下降"的证明。
