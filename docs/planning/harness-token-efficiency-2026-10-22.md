# Graph harness 价格加权成本：2026-10-22

分支 `feature/harness-token-efficiency-2026-10-22`（从 `main` 另开，每次 `main` 前进就 rebase 一次；正文写的数字对应 `main` 的 `255b3d25`）。
本轮目标：降低**每个完成任务**的价格加权成本，质量不下降。

**报告里引用的提交号都是 rebase 之后的当前分支上的号**（`git branch --contains <hash>` 能查到）。用 `node scripts/report-commit-links.mjs docs/planning/harness-token-efficiency-2026-10-22*.md` 可以在再次 rebase 后自动把它们重指向。

本报告分七篇：**[基线](harness-token-efficiency-2026-10-22-baseline.md)**（量到什么）· **[已做的修改](harness-token-efficiency-2026-10-22-changes.md)**（做了什么、怎么验证）· **[真实模型 A/B](harness-token-efficiency-2026-10-22-ab.md)**（量到的与量不到的）· **[A/B 重跑](harness-token-efficiency-2026-10-22-ab-rerun.md)**（把账本放进仓库之后又测到的东西）· **[提案与缺口](harness-token-efficiency-2026-10-22-proposals.md)**（只提案的那部分与还欠着的部分）· **[验证与证据](harness-token-efficiency-2026-10-22-verification.md)**（门禁、每处改动的红灯证据、证据文件的位置）。

结论摘要：

1. 上一轮审计（`harness-token-efficiency-2026-10-16.md`）写的是已退役的 TypeScript 侧车。**live 路径已经换成 Go + PiG 内核，静态上下文不再是主要开销，话上下文的大小才是。**
2. 基线（真实库只读快照）：19,608 次请求、129 个 task、4,432,477,135 个缓存读取 token。缓存读取占 token 总量 96.8%，按计费类型折算后占花费 **42.7%**；未缓存输入 36.1%，输出 21.2%。
3. **每一次请求携带的前缀平均 246,440 个 token**（中位 235,497，p90 450,048，max 673,408）。这是最大的单一开销来源，而它的大小完全由**压缩阈值**决定：会话在到达供应商窗口前才压缩，实测压缩前中位 495,979 token、压缩后中位 27,158 token。
4. 静态前缀（系统提示 + 工具声明）在主会话里约 15,701 token，只占平均前缀的 **6.4%**。这解释了前一周工具卸载实验为什么没有降本（浏览器按需加载反而贵 39%，目录工具按需加载贵 3.35%）：在 246K 的前缀里省 2K token 是 0.8%。
5. 已提交 6 处修改（各自独立可回滚的提交）：助手回合如实回放（reasoning + tool_use）、Anthropic 传输显式缓存断点、可由环境变量命名的压缩上限、摘要拿到它自己要的输出预算、任务说明包不重复发送、成本 CLI 增加前缀分布、用途拆分、整树情景计价与压缩次数。
6. 压缩失败的根因也找到了：请求自己的输出预算在内核桥上被丢掉，摘要被按模型的整个上限要（生产模型 384,000），于是摘要写到被切断为止——9 次失败里 6 次是这个原因，而失败的压缩会把 496K 的上下文留在会话里。
7. **会话上下文的第二块重复**：任务说明包在每次 operation 里重发同一段环境说明（实测 62 份里 89.5% 逐字相同，占 transcript 20%）。已做成默认关闭的 `GRAPH_REUSE_TASK_SETUP`，去掉重复约等于上下文 −18%。

**真实模型 A/B 跑了**（command-goat 订阅内、边际费用 0 的模型 `deepseek/deepseek-v4.1-flash`、Go 后端、独立行为检查、22 次通过检查的运行；另有 parser、command、长会话三组共 30+ 次运行）。**最后又在本分支当前的代码上重跑了两组，逐次原始账本进了仓库**（[§5.7、§5.8](harness-token-efficiency-2026-10-22-ab-rerun.md)）。

**最重要的一条结论不是哪个改动省了钱，而是"省前缀"在什么负载上才值钱**：一个前缀缩减值多少，取决于**缓存读取占这次任务花费的比例**——短任务（上下文 12K）里缓存读取只占 8%，生产会话（上下文 246K）里占 42.7%。**同样的前缀缩减，在短任务上不值钱，在生产会话上值 5 倍。** 所以这个任务集上三个杠杆全都测不出差别（接缝：花费差 −1.7%，t=−0.10；说明包复用：长会话里缓存读取 −17.6% 但花费平；压缩上限：根本不触发）。

**重跑那两组第一次把机制量出来了**（[§5.7、§5.8](harness-token-efficiency-2026-10-22-ab-rerun.md)，逐次原始账本已进仓）：接缝**把每次请求的前缀压小 18.2%（一轮，t=−2.13，显著）/ 25.2%（八轮，n=2）**；但一轮那组**同时把字节从"缓存读取"挪进"未缓存输入" 40.4%（t=+2.40，显著）**——总量是降的（−12.4%），**降下来的字节从便宜的桶跑进了贵 50 倍的桶**，所以花费的点估计是 +14%（t=+1.30，测不出）；八轮那组未缓存输入反而降了 16.0%，花费 −12.2%（但每组只有 2 次，区间宽到不能做统计）。原因是那个任务的提示词明确要求"读完它的完整输出"：接缝把大结果换成摘要 + 句柄，模型接着把句柄读回来，**那些字节是新内容，按未缓存输入计价**；读完之后留在前缀里，后面的轮次就从缓存读它。

**所以要改一句定性的话**：**接缝是"省前缀的杠杆"，不是"省钱的杠杆"**。前缀省下多少是真的；钱省不省，取决于省下的字节本来在哪个桶、模型会不会回读、以及之后还跑多少轮。

站得住的是：接缝的**机制与幅度**（真实输出 78,934 字符 → 模型读 19,959 + 句柄，句柄逐字节齐全；前缀 −18.2%，显著）、说明包复用的**前缀缩减**（−17.6%，实测）、以及按生产负载形状代进去的**价值排序**（上限 −29% > 说明包 −7.6% > 接缝 −2.2%）。

**往生产形状靠的两组（15 轮长会话、8 轮大输出）给出了最有用的一条**：接缝开着时上下文稳在 16K、接缝关掉能长到 34K；接缝开着的那两次运行**花费几乎一样（11% 带宽）**，关掉它的两次**差了 2 倍**——因为上下文不再能鼓起来，一次任务花多少就取决于模型这一轮又跑了几次大命令。**接缝真正的作用是让上下文不再鼓，也让轮间花费不再散。** 32K 的压缩上限在两组里一次都没触发：生产那 496K 是 62 轮**重**工作攒出来的，脚本化任务跑 8 轮只到 16K。

**按真实请求序列重算后，排序变了**（§5.6）：把生产主会话那 1,043 次真实请求逐条重建（前缀 = 静态前缀 + 之前所有内容），省下的字节要乘以后每一次请求——**接缝 −13.7%（$1.34）、说明包复用 −9.7%（$0.95）、两个一起 −23.4%（$2.30）**，换算到整棵树是 4.7% / 3.3% / 8.1%。按"平均前缀"估的 −2.2% **低估了一半**。**注意这是上限**：那个模型假设模型不会把落盘的文件全读回来，[§5.7](harness-token-efficiency-2026-10-22-ab-rerun.md) 说明了这个假设不成立时会怎样。

**尚未证明**："每完成任务成本下降且质量不降"——三个杠杆在短任务上**都测不出钱**（接缝重跑 n=6/组：花费差 +14%，t=+1.30；说明包复用：长会话里缓存读取 −17.6% 但花费平；压缩上限：根本不触发）。**原因不是改动没用，而是短任务里缓存读取只占花费的 8%，生产会话里占 42.7%**——省前缀在短任务上不值钱，在生产会话上值 5 倍。站得住的是机制、字节和方向，不是账单。

**"怎么测"这一步也推进了**（§5.5）：要量到钱，需要**每轮都产出大输出的长会话**（接缝开/关的上下文 16K vs 34K、花费带宽 11% vs 2 倍），而不是把短任务拉长——脚本化的短任务跑 15 轮也只到 14K，上限根本不会触发。

### 两个必须知道的边界

- **主 Agent 会话在 Go 内核上，开发者/CLI 路径（`src/server/`）在 TypeScript SDK 上。** 两者共用同一个 `tasks.sqlite`，但提示词拼装与请求装配各有一份。本轮的 Go 修改只覆盖生产路径；`src/runtime/compaction.ts` 的同名修改保持两边一致。
- **压缩是 daemon 驱动的，内核自己的阈值是关的**（`resident.go:82`：`Enabled: false, ReserveTokens: 4096, BackgroundTokens: 0`；4096 是本轮为了放得下交接摘要提上去的）。所以阈值改一处即可覆盖主会话。

**结论：第 6、7、8 项（前一周的重点）在当前阈值下没有杠杆。** 静态前缀只有 6.4%，把它砍掉一半也只值 1.4%。如果先降阈值（把平均前缀压到 77.6K），静态前缀占比升到 20.2%，工具裁剪才值得做。**顺序很重要。**
