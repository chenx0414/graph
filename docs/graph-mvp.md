## 目标与首位使用者

首位使用者是项目作者。Graph 接受已有项目的功能需求，与使用者讨论并形成可验收说明，再自动拆解任务、安排并行工作、交接上下文、检查、审查、返工并合并代码，减少人工拆任务、转发上下文和持续盯进度。

首版一次执行一个功能任务，其余排队；发布由使用者决定。

执行中提出新增功能时，创建新的功能任务并进入队列，原任务继续原验收范围。例如“按标题搜索”之外增加“搜索笔记正文”，属于新任务，而非扩大原任务并使其已有结果失效。原范围内的说明澄清仍按暂停、评估影响、继续的规则处理。

## 产品形态与技术约束

- 本机 Web 界面，后台执行独立于界面生命周期。
- 关闭界面后继续执行；程序重启后从持久进度核查并恢复。
- Pi Agent 与 TypeScript 是硬约束；LangGraph、Rust 在访谈中为候选，实现规划选择首版不引入，理由见 [架构](architecture.md)。
- Pi 作为 Agent 内核的能力依据见 [能力核查](pi-capabilities.md)。任务图、预算与外部操作恢复仍需 Graph 负责。
- 界面展示自动生成的任务图、运行状态、待处理问题；允许暂停、补充说明与继续。首版无需手工编辑图。

## Agent 库、实例与能力库

- 主管即 Master Agent / main agent，是直接与使用者对话的 Agent。
- Agent 库是人才库，定义预先配置 Skills、MCP 等并带推荐模型等级。具体模型不属于定义身份。
- 每次派出独立实例，记录定义版本和所选模型等完整运行配置。
- 一个实例只对应一个 Agent 节点。同一定义可派出多个实例；回环返工回到原节点，沿用原实例、会话、工作副本和累计额度。
- 首版主管通过程序接口创建 Agent，程序校验模型、能力、权限及并发限制；不要求独立的 Agent 创建者角色。
- 主管可自主搜索、安装新 Skills、MCP、扩展，保存到 Graph 管理的能力库并记录来源与版本，供以后复用。
- 主管可自主创建、保存 Agent 库条目；更新生成新版本。运行中实例保留原定义版本，后续实例可使用新版。
- 运行中实例继续遵循已确认的原定义版本规则；新增能力可用于后续定义和实例。安装能力不自动扩大任务权限。

## 模型选择与切换

- 使用者配置可用模型、低/中/高/最高等级及偏好，主管据此选择。
- 实现与审查使用不同模型和独立上下文，不强制不同厂商。
- 模型不可用时仅从已配置候选替换。保持节点、实例、工作副本与累计额度，记录切换并交接上下文。
- 对应审查避开参与过该轮实现的模型，无合格候选时暂停该节点。

## 任务图与正式状态

- Agent 节点由唯一实例承担，可循环执行。
- 程序节点执行测试、合并、条件判断等，不占 Agent 名额；普通工具调用不必全部展开为节点。
- 子图为可展开容器，内部仍为上述节点；容器不额外代表 Agent，输出结果、产物与证据。
- 主管可在已确认需求与额度内动态调整图，保存每次变更原因和版本。
- Agent 提交结果、证据和状态变更请求，由 Graph 执行程序统一校验并记录；主管负责规划和返工，程序负责规则、额度及状态一致性。
- 新增功能单独形成新任务并确认需求；改变原任务验收标准或突破额度需要使用者确认。

## 首版全部图模式

支持原草稿全部模式，并可组合、嵌套：

- 扇出扇入。
- 主管-工人。
- 流水线。
- 条件路由。
- 评估-优化循环。
- 对抗式验证器。
- 多视角验证器。
- 评委式验证器。

汇合默认等待所有必需分支成功；失败分支重试或返工，成功结果保留。仅预先标为可选的分支允许缺席，不能临时降低要求以绕过失败。

对抗式反驳必须附证据，有未解决且影响验收的有效反例就不通过，不能仅靠多数票压过反例。多视角验证要求所有必需维度通过，建议项不阻塞。评委式先检查硬性要求，再按预定标准排名；全部不合格则返工，胜者吸收其他方案后重新验证。

## 上下文与代码协作

- 每个子 Agent 持有独立会话和工作副本。
- 自动生成任务说明包：目标、验收条件、相关决策、依赖产物与文件位置。
- 子 Agent 可自行读取共享资料或向主管提问；完成后提供结论与证据，主管按需查看完整记录。
- 共享空间存放任务说明、证据与产物；代码在独立副本修改，通过分支合并集成。
- 明确依赖的代码修改串行执行。
- 各 Agent 修改先汇入任务集成分支，通过整体测试和独立审查后自动合入启动时指定的目标分支。
- 目标分支有新变化时先纳入集成分支，重跑受影响的测试和审查；冲突需要改变已确认需求时找使用者。

## 并发、预算与费用

- 全图含子图最多 10 个正在执行的 Agent，主管同样占名额。
- 等待依赖或结果时释放名额，恢复前重新获取，实例身份与会话不变。
- 单 Agent 累计额度 20,000,000 token，按每次请求输入与输出计量，缓存输入不在同一次请求重复计算。
- 重试、返工、恢复和模型切换不重置额度；耗尽的工作需使用者追加额度。
- 新调用准入尽量预留输入与最大输出；达到上限禁止新调用，实际超出完整记账。
- 用量缺失标为待核对并暂停该 Agent，不能当作零消耗继续运行。
- 运行时长不限。
- 按配置价格计算并标明估算费用；实际账单可用时核对，未知价格显示未知。

## 暂停、恢复与人工介入

- 点击暂停后，已发出的调用可结束，不再发起下一个模型或工具调用；全部停稳后显示已暂停。
- 补充说明后先重新评估受影响任务，再继续。
- 有证据的已完成步骤可复用；中断模型调用重新发起并计入额度。
- Git、文件写入等先核查实际结果，再决定补做；无法判断且重复执行可能改变外部结果时找使用者。
- 节点受阻时暂停该节点及依赖它的后续节点，独立分支继续；整项需求或任务权限问题暂停全任务。
- 待处理问题集中展示并保留现场等待回复。
- 连续三轮无实质进展时附争议、尝试和证据找使用者。一轮是实现或修复及其后的检查与审查。
- 有证据关闭阻塞问题、通过此前失败的验收项算进展；改写说明、重复修改、跳过失败测试不算。检查标准变化须可追踪。

## 权限与验收

- 默认允许工作副本内代码修改、构建测试、依赖安装与资料检索。
- 主管可在使用者预先授予范围内批准额外目录写入和外部服务操作；新 Agent 继承任务权限上限，由程序落实。
- 扩大权限、追加额度、发布由使用者决定。
- 需求讨论结束时固定验收项，并记录检查方式与证据要求。
- 自动合并必须通过验收项、相关回归检查和独立审查；降低或删除验收要求需使用者确认。
- 人工检查项等待使用者处理。

## 运行观测

## Graph 首版完成标准

以下两组验收已由使用者确认，均需完成。

### 真实任务验收

由 Graph 完成上述 MediaBookmarks B站 Web 应用闭环，交付代码、测试、独立审查结论并自动合并到指定目标分支。使用者无需人工拆任务或转发上下文；需求确认、登录等人工操作及规定的介入不算自动化失败。

### 执行机制验收

每种图模式都有可执行案例。异常场景采用可控测试复现，覆盖：

| 范围 | 必须证明的行为 |
| --- | --- |
| 全部图模式 | 扇出扇入、主管-工人、流水线、路由、评估-优化及三类验证器均可执行，判断符合预定规则。 |
| 嵌套与并发 | 全图及子图最多 10 个执行中 Agent；等待释放名额，恢复重新获取，程序节点不计入。 |
| 分支失败 | 必需分支失败阻塞汇合，独立分支可继续，已成功结果可复用。 |
| 返工循环 | 回到原实现节点和实例，保留会话与额度；连续三轮无实质进展时保存证据并等待介入。 |
| 预算 | 请求计量不重复，重试/恢复/换模型不清零；准入检查、实际超额记账和用量缺失暂停生效。 |
| 模型切换 | 从允许候选切换并保留实例身份，审查避开该轮实现用过的模型；无合格模型暂停。 |
| 权限 | 程序落实任务上限，主管授权不超范围，新增 Agent 或能力不绕过约束。 |
| 暂停与恢复 | 已发调用结束后停稳，不发下一调用；重启复用已完成结果，结果不明的操作先核查。 |
| 代码集成 | 自动合并满足验收、回归和独立审查；目标分支变化先集成重检，需求冲突等待用户。 |
