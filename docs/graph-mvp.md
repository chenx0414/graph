# Graph 产品范围与执行规则

当前契约：2026-10-01 定稿的 [Graph v2 规格](specs/graph-rebuild-v2.md)，以及使用者确认的 [ADR 0030](adr/0030-graph-v2-interface-delivery-kernel.md)。本文为实施时使用的产品范围摘要；详细字段、默认值和验收要求以定稿规格为准。当前实施及证据见 进度记录（该文档已删除），不能把已有门禁通过解释为全部交付已完成。

## 产品目标

Graph 为 main Agent 提供清晰、直观、可动态调整的协作运行空间。main 位于 graph 外部，直接服务使用者，可以同时创建与管理多个 graph；graph 结束不结束 main 的会话。

图的正式对象是 Agent 节点、边、模块和共享产物。子 graph 复用这些对象的定义与公开接口。Agent 负责工作，模块负责控制流，宿主负责协议、持久状态与执行约束。界面展示真实结构和投递事实，不推断另一套依赖图。

main 以完整声明式 JSON 定义构建 graph，在运行中使用带 baseRevision 的局部 patch。YAML 只用于文档示例。配方定义身份、规则与能力；节点定义具体任务、执行指令、验收、接口、工作位置、模型与预算。instructions 与 task 摘要分开：main 为新节点填写非空指令，历史省略字段的定义继续可运行；指令随 execution 冻结，修改后下一轮生效。

同一个功能任务沿用同一个 graph。确认前默认原地修改当前草稿，保留草稿版本号；main 自行判断是否值得另存一个版本作为里程碑或供比较，不必因每次修改都增加版本，也不必为是否另存版本向用户请求许可。确认后的返工、结构调整和配置修改使用原 graph 的 patch；执行修订仍保留审计记录。

草稿版本只做追加与原地修改，不再提供归档、恢复或删除（2026-11-07 删除）。历史草稿版本保留在 `proposalHistory` 中只读展示，正式任务、graph、聊天、执行记录与验收事实不受影响；现有草稿不自动批量清理。

原地修改会更新草稿内容修订标识。确认必须携带读取草稿时的修订标识；内容已经变化时拒绝确认，要求重新读取，防止用户确认到未经查看的新内容。

## 接口、投递与队列

- 节点可以有多个具名逻辑输入、输出；概览视觉上合并为一个入口和出口。
- 边是持久连接，投递是一次实际发送的信息。连接两端必须引用相同协议 ID 和版本，终点输入规定接收协议；不同协议通过显式映射模块连接。
- submit 选择本节点输出，可只提交部分输出；遗漏等价于 enable:false。一次 execution 最多一次有效提交，但提交与执行结束独立。
- 宿主先校验全部输出与全部启用终点，全部通过后在同一事务受理。失败不消耗有效提交机会，允许按字段错误修正。
- enable:false 不发送、不启动下游、不覆盖模块输入；业务不通过为 enable:true 并传递 passed:false 等协议内容。
- 同一输出向所有启用连接广播。无接收方仍记录有效提交并返回提示；公开 graph 输出映射也算接收方。
- 一个节点串行处理接口投递与聊天；默认一条投递对应一次执行，忙时排队，空闲时启动。汇合由模块显式实现，节点队列不隐含合并输入。
- 复跑沿用自己的会话与累计预算。聊天可以只回复；任务执行的必需输出由正式节点配置声明，不能只写在 prompt 中。
- main 可直接投递到具名输入，遵守相同协议和排队规则。Agent 间聊天使用稳定身份，不能伪造发送者或 execution 身份。

## 模块与子 graph

模块具有具名输入、输出及明确判断规则。每个输入保存最新有效投递；未收到、false、null 必须可区分。普通规则支持取值、布尔组合、比较和输出映射，不执行规则字符串中的任意代码。

触发策略 each 在每次有效输入更新后判断；once 条件满足后发送一次并保留输入状态。main 或明确声明的控制输入可以重开 once：只解除已触发状态，保留已有输入，等下一条投递再判断。不提供隐含清空或立即再次发送。

自定义模块代码在受限执行环境中运行，具有明确 CPU、内存、超时和输出上限。workspace.command 是具有宿主权限与副作用恢复记录的模块能力，不是独立工具节点。模块代码不能因为属于 graph 就获得未授权能力。

子 graph 有公开输入、输出映射，同一定义可创建多个独立实例。它不额外执行 Agent，不隐含等待所有内部节点结束，不引入第二套调度器。内部会话、队列和模块状态独立，产物空间共用顶层 graph 的空间。

## 常驻进程、配置与恢复

每个 graph Agent 节点拥有一个常驻 Pi 进程，服务至 graph 结束；一次执行结束后保留节点与聊天历史。进程崩溃可以重建，但节点身份、历史、队列、预算和提交事实不得重置。身份或能力变更在两次 turn 之间受控重绑。

首次输入包含 graph 概述、任务、验收、接口协议、实际 value、提交要求及有效能力。复跑只发送新输入与必要配置变化。完整结构按需读取。用户可查看实际 system prompt、工具和当前执行配置，并区分下一次配置预览。

未提交执行异常默认自动重试 2 次，共 3 次尝试；缺失必需输出默认补交 1 次。两类计数独立，重启不清零。成功提交不可撤回，不因后续错误重复发送；已提交执行只处理剩余工作。未知副作用先核查，权限与预算拒绝不盲重试。最终失败保留输入、暂停本节点队列，通知 main 处理，独立节点继续。

## 动态修改与结束

patch 整体校验并产生新修订。当前 execution 配置固定，下一次执行采用最新节点配置；已受理投递保留接收时协议与来源。禁用或删除边只阻止以后投递，取消已有任务是独立操作。

有执行中、排队或失败待处理工作的节点、模块、输入不得直接删除；须先处理或明确取消，等待当前工作停稳。删除节点结束其 Pi 服务并移除连接，保留聊天、产物和执行历史。禁止通过改名、新实例或配置切换清空累计消耗。

空闲仅表示当前没有工作。默认由 main 显式完成，也可声明完成出口。完成请求关闭外部新任务输入与触发执行的聊天，允许已受理工作的内部投递继续清空；满足正式验收后结束。stop 则明确取消剩余工作。完成或停止后的记录仍可查看。

## 共享产物与代码验收

产物支持文件、Markdown 文本、JSON；发布产生稳定版本，修改后再发布。引用指向精确 artifactId、version 和 digest。普通 Agent 修改自己的产物、读取其他已发布产物；main 可修改全部产物，并记录修改者。

graph 内 Agent 的 `artifact_list` 只列当前顶层 graph 的共享产物，子 graph 共用该范围；项目级提升产物不混入节点列表。main 继续发现其任务产物和项目共享知识。

代码成果必须包含稳定 commit，worktree 是访问位置。审查结论记录实际审查版本。模块可以保留早先通过状态，但旧通过不能自动证明新的 commit 已审查。最终验收核对实际检查、独立审查与人工确认的精确版本。

有代码交付时，变更经显式 Git 集成路径进入任务集成分支。合入目标分支前保持已确认验收、检查与独立审查；目标变化、脏工作区和未检查的集成变化不能绕过这些条件。非代码 graph 不强制建立 Git 交付。

## 能力、模型、权限与预算

继续使用能力库、版本化配方库和已配置的供应商、模型目录。模型目录分 small、medium、frontier；历史 low、high、highest 配置和配方保留兼容含义，不静默改写。具体选择、配置和低频能力通过指导文档按需读取。

工作位置和访问范围显式配置，节点权限受宿主授权上限限制。能力绑定不替代路径、网络、凭据、并发或预算约束；拒绝不得通过切换执行方式或静默扩大权限绕过。

main 与多个 graph 共用全局执行名额，最多 10 个正在执行的 Agent。空闲常驻进程不占执行名额，等待释放名额，恢复前重新准入。

默认节点 token 预算不限；配置有限额度时，复跑、补交、重试、恢复和换模型都延续消耗。用量来源和未知费用明确保留；有限预算下不可核算的已发调用需核对，不当作零。运行时长、工具调用、token 和等待时间取自实际记录。

问题区分 main 与 user 所有权。执行恢复与协调问题先通知 main；预算追加、权限扩大、人工验收或明确产品变化按已有用户授权规则处理。运行通知与公开业务输出分开表达。

## 可视化与交付验收

节点和正式边自动沿统一格点排列，方向与位置稳定，运行状态叠加在结构上。边详情显示具名接口、真实 value、来源、协议、接收状态和历史；模块详情显示输入、缺失状态、条件判断、触发策略、实际输出及重开历史。

子 graph 可逐层折叠与展开，保留跨边界连接与公开接口，不改变执行状态。点击 Agent 打开独立聊天窗口，多个窗口可并存；关闭窗口不停止 Agent。大 value 和日志分页、按需全文读取，SSE 用游标恢复。

所有 graph 入口必须统一使用新内核。按 ADR 0030 丢弃旧 graph 与旧图历史，删除旧 DAG、特殊 loop、转换器和旧历史 reader；保留模型配置、能力库、配方、外部 main 会话及共享基础设施，不重建整个用户数据库。

完成要求涵盖规格全部八阶段、真实 Pi/Git/HTTP/browser 的行为验收，以及默认用户应用的实际切换与窗口验证。库级测试通过、包构建成功或临时隔离探针不能单独证明整体产品已经交付。历史 M0–M7 报告与 [产品化报告](planning/productization-reports.md)保留为以前阶段的证据，不作为 v2 默认应用完成结论。
